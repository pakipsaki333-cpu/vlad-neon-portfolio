# Telegram-бот Doss — спецификация и план

Бот — самый дешёвый способ раздать доступ и брать «символическую подписку»
без стора, эквайринга и юрлица. Ниже — рабочий дизайн, который можно
реализовать за один-два вечера поверх уже готового CLI `doss`.

## Роли

- **владелец** (`OWNER_TG_ID`) — видит статистику, может выдавать `unlimited`;
- **свой** (allowlist) — бесплатно, без лимитов;
- **платящий** — 119 ₽/мес эквивалент, лимит 200 ГБ;
- **триал** — 3 дня / 10 ГБ, один раз на Telegram-id.

## Команды

| Команда | Что делает |
|---|---|
| `/start` | онбординг: 3 экрана — «что это», «как подключить», кнопка «Попробовать» |
| `/trial` | создаёт триал-аккаунт, отдаёт ссылку `vless://` + инструкцию по Hiddify/v2rayNG |
| `/me` | срок, остаток трафика, ссылка-подписка, кнопка «Продлить» |
| `/buy` | инвойс Telegram Stars (`XTR`), 30 дней |
| `/support` | связь с владельцем |
| `/admin` (только владелец) | список юзеров, ручная выдача, ревок, бэкап state.json |

## Поток оплаты (Stars)

```
/buy → sendInvoice(currency="XTR", prices=[{label:"30 дней", amount:150}])
     → pre_checkout_query → answerPreCheckoutQuery(ok=True)
     → successful_payment → продлить срок +7/+30 дней → отдать свежую ссылку
```

Почему Stars: не нужен эквайринг, нет чарджбэков, работает из РФ без карты.
Вывод — на кошелёк Fragment. Альтернативы (когда захочется): крипта
(USDT TRC-20 / TON) с ручной сверкой, потом ЮKassa, если появится ИП.

## Данные (SQLite, минимум полей)

```sql
CREATE TABLE users (
  tg_id      INTEGER PRIMARY KEY,
  doss_name  TEXT UNIQUE NOT NULL,   -- имя в /etc/doss/state.json
  status     TEXT NOT NULL,          -- trial|paid|friend|owner
  trial_used INTEGER NOT NULL DEFAULT 0,
  expires_at TEXT,                   -- ISO-дата, NULL = бессрочно
  traffic_gb INTEGER,                -- NULL = без лимита
  created_at TEXT NOT NULL
);
CREATE TABLE payments (
  id TEXT PRIMARY KEY,               -- telegram_payment_charge_id
  tg_id INTEGER NOT NULL,
  amount INTEGER NOT NULL,
  currency TEXT NOT NULL,
  days INTEGER NOT NULL,
  created_at TEXT NOT NULL
);
```

Никаких логов трафика, IP, посещённых сайтов. Это и политика приватности,
и защита от претензий.

## Как бот общается с сервером

Три варианта, по возрастанию сложности:

1. **SSH + CLI** (для MVP): бот на дешёвом VPS/том же Oracle вызывает
   `ssh doss@server 'doss user add ...'`. Ключ — только на чтение/вызов CLI,
   `command=` в `authorized_keys` ограничивает одной командой-обёрткой.
2. **HTTP-API рядом с сервером** (для роста): маленький сервис (FastAPI),
   дергает тот же CLI, авторизация — HMAC по времени. Даёт метрики и очередь.
3. **Xray API** (`statsquery`) — реальный учёт трафика по `email`-пользователю.

Рекомендуемый путь: 1 → 2 → 3, не раньше, чем появятся первые 20 платящих.

## Что не делать

- не публиковать бесплатные конфиги в самом боте/канале — их соберут сканеры;
- не выдавать по одному `vless://` на всех: один uuid на человека — иначе
  ревок одного ломает остальных;
- не хранить в боте номера карт/паспорта — Stars и крипта это закрывают;
- не обещать «безлимит» на бесплатном узле с 10 ТБ трафика.
